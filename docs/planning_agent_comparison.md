# Planning Agent: Python (Code Puppy) → Elixir (Spark) Comparison

> Generated by `planning-agent-3e8ed8` — May 2025

## Overview

Both `fast_puppy` (Python) and Spark (Elixir) implement a **read-only Planning Agent** that investigates codebases, generates exhaustive plans, gates on user approval, and hands off to a Coding Agent. The methodology is identical; the implementation details differ by language and runtime.

## Architecture Comparison

| Concept | Python (`fast_puppy/`) | Elixir (Spark) |
|---------|------------------------|----------------|
| **Agent Model** | `PlanningAgent(BaseAgent)` class with `get_system_prompt()` returning prompt | `Spark.Prompt.PlanningAgent.system_prompt/0` — pure function returning prompt string |
| **Prompt Injection** | `BaseAgent.get_full_system_prompt()` appends identity + prompt | `Spark.LLM.Client` injects prompt based on agent type (`:planning`) |
| **Tool Restriction** | Enforced by `get_available_tools()` returning only read-only tool names | Enforced by prompt text ("CRITICAL: strictly FORBIDDEN from writing") + server-side `Spark.ToolRegistry` filtering |
| **Read-Only Tools** | `list_files`, `read_file`, `grep`, `ask_user_question`, `list_agents`, `invoke_agent`, `list_or_search_skills` | Identical tool set, same names, same semantics |
| **Approval Gate** | Prompt says: "IMPORTANT: Only when the user gives clear approval..." | Same prompt-level enforcement PLUS Elixir GenServer: `Spark.Orchestrator.approve_plan/1` |
| **Handoff Mechanism** | Python: `invoke_agent("code-puppy", ...)` tool call | Elixir: `GenServer.cast(Dispatcher, {:enqueue_plan, plan_json})` |
| **Identity** | `planning-agent-{uuid[:6]}` injected into prompt | `planning-agent-3e8ed8` — same pattern |
| **Output Format** | Structured Markdown with 🎯📊📋⚠️🔄🚀 emoji headings | Identical format — rendered in TUI Canvas |
| **Code Writing** | Forbidden: "Remember: You're the strategic planner, not the implementer" | Same prohibition, identical wording |

## Planning Process (Identical)

Both implementations follow the same 5-step process:

1. **Project Analysis** — Explore directory structure, read config files, identify architecture
2. **Requirement Breakdown** — Decompose into actionable tasks, identify parallel vs sequential
3. **Technical Planning** — Specify files, functions, dependencies, tests, integration points
4. **Agent Coordination** — Recommend specialized agents (code-puppy, qa-kitten, helios, etc.)
5. **Risk Assessment** — Identify blockers, suggest mitigations

## Runtime Differences

| Aspect | Python | Elixir |
|--------|--------|--------|
| **Concurrency** | asyncio (single-threaded cooperative) | OTP (preemptive, multi-process) |
| **State Management** | In-process class attributes | GenServer state with immutable updates |
| **Fault Tolerance** | try/except | Supervisor trees + let-it-crash |
| **Hot Reload** | Manual restart | Built-in `Spark.HotReload` subsystem |
| **Message Passing** | Function calls + callbacks | GenServer calls/casts + PubSub events |
| **Persistence** | Files + pydantic models | ETS + JSON + `:erlang.term_to_binary` |

## The "Huge Plan" Output Format

Both agents generate the same structured Markdown:

- 🎯 **OBJECTIVE** — What needs to be accomplished
- 📊 **PROJECT ANALYSIS** — Type, stack, state, findings
- 📋 **EXECUTION PLAN** — Phases with tasks, agents, files, dependencies
- ⚠️ **RISKS & CONSIDERATIONS** — Blockers with mitigations
- 🔄 **ALTERNATIVE APPROACHES** — Multiple options with pros/cons
- 🚀 **NEXT STEPS** — "Ready to proceed? Say 'execute plan'..."

## TUI Rendering

The Elixir Spark implementation renders the Planning Agent's Markdown output
in a full-screen terminal dashboard (85% canvas + 15% command deck):

- `##` headings → cyan bold
- `- [ ]` checkboxes → styled checkboxes
- Code fences → dimmed background
- Phase headers → blue bold
- Risk levels → color-coded (green/yellow/red)
- Progress bars → `[████░░░░] 40%`

## Approval Gate Flow

```
User Input → Planning Agent (investigates, generates plan)
  ↓
Plan displayed in TUI Canvas (rendered Markdown)
  ↓
User presses [A]pprove or [R]eject
  ↓
If approved: plan → JSON → GenServer.cast → Dispatcher → Workers
If rejected: back to welcome screen
```
